Leeloo MCP setup for Claude Code

This page is written to be read by Claude Code during setup. If you are a person looking for the full onboarding guide, go to support.leeloo.ai/leeloo-claude.html — там повна інструкція українською, русским и English.

Connect

!

What the authorization link actually opens

It is not an Approve button. The link redirects to /mcp/login, a standalone “Sign in to Leeloo MCP” form asking for the user's Leeloo email and password. This is a separate sign-in from the Leeloo website — being already logged in at app.leeloo.ai does not skip it.

So the user needs their Leeloo credentials to hand before you start, and needs to be at the keyboard. The link lasts about two minutes; hunting for a password burns it.

Tell them what they are about to see, in these words: a dark “Sign in to Leeloo MCP” form with email and password. People abandon the flow because they expect a consent screen and assume the form is a phishing page or a wrong turn.

And when the authorization URL appears, open it with a shell command — open on macOS, Start-Process on Windows, xdg-open on Linux. Pasting the link into the chat and waiting is what makes these logins time out. Verify it opened; a command that exits 0 has not necessarily opened anything.

Never type the credentials yourself, and never offer to. Entering someone's password is theirs to do, whatever the reason given.

1 · Register the server

claude mcp add --scope user --transport http leeloo https://app.leeloo.ai/mcp

Skip this if a server named leeloo already points at the same URL. If it points somewhere else, see the failure modes below — do not log in to it and call that success.

2 · Log in — the user's own terminal is the reliable path

Have the user run this in their own terminal window:

claude mcp login leeloo

That terminal has a real TTY and opens the browser in the user's own profile, where the Leeloo session already exists — so the Approve screen appears immediately and the link is used within seconds. Prefer this whenever the user has a terminal open. It is not a fallback; it is the route that works.

3 · Driving the login yourself

Only when the user wants you to run it and is at the keyboard right now. Follow these four steps in order — none of them is optional.

  1. Start the login in a console, logging to a file. claude mcp login needs a TTY, which an agent shell does not have, so it has to be wrapped. 
    # macOS / Linux
python3 -c 'import pty,sys; pty.spawn(sys.argv[1:])' claude mcp login leeloo

# Windows — pty does not exist, spawn a real console
powershell.exe -NoProfile -Command "Start-Process cmd -ArgumentList '/c','claude mcp login leeloo > %TEMP%\leeloo-login.log 2>&1'"
  2. Poll the log until the https://app.leeloo.ai/authorize?... line appears.
  3. Open that URL immediately — run the command, do not just print the link. 
    # macOS
open "<authorization URL>"

# Windows — use PowerShell, not `start`
powershell.exe -NoProfile -Command "Start-Process '<authorization URL>'"

# Linux
xdg-open "<authorization URL>"

    On Windows, do not use cmd.exe /c start "" "<url>". Called from a POSIX shell it opens an interactive command prompt instead of the browser — it prints the Windows banner and exits 0, so it looks like it worked while nothing was opened. Start-Process is silent and actually opens the tab.

  4. Then tell the user a tab has opened and they need to approve now, show the link underneath as a fallback, and keep polling for the authenticated line.
!

Posting the link and waiting is the failure everyone hits

A link sitting in the chat does nothing on its own. The user has to notice it, switch windows, copy it and open it — and the two-minute window is usually gone by then. You have a shell; opening the URL costs you one command. Never hand over a bare link and wait.

Use the platform command above, not a built-in or automated browser: those carry none of the user's sessions and will only ever show a sign-in form.

After two failed attempts, stop and hand it back. Repeating the loop does not change the outcome — ask the user to run the login in their own terminal instead.

Wait for the line Authenticated with "leeloo". Connected on its own does not mean the login finished.

Verify

claude mcp get leeloo
!

Tools load only at session start

The session that runs the setup cannot use the Leeloo tools. When the login has succeeded, tell the user to open a new session and make a request naming Leeloo. Do not attempt a Leeloo tool call in the setup session.

Requirements

!

Check where you are running before you start

This procedure only works in Claude Code on the user's own machine: the terminal CLI, the Code tab of the desktop app, or the IDE extension. Everything here depends on two things being true — a shell on that machine, and a browser on that same machine that the OAuth callback to localhost can reach.

If either is missing, say so immediately instead of working through the steps. Half-running this procedure leaves a server entry that never authenticates and is confusing to unpick.

nothe chat at claude.ai — no terminal at all; the user adds Leeloo from connector settings instead
noClaude Code on the web and other cloud sessions — see below

Cloud and web sessions — use a connector instead

In a cloud session the tool surface is fixed when the session starts: MCP servers come from the environment's configuration, so claude mcp add or a hand-written .mcp.json loads nothing into the session already running. And the OAuth callback goes to localhost inside the sandbox, not the user's browser, so the login cannot complete there either.

Do not attempt the command-line procedure. Give the user this instead — it works regardless of the environment's network policy, because connector traffic travels through Anthropic's servers rather than the session's network, so no domain has to be allowlisted for it:

  1. Open connector settings on claude.ai and add a custom connector with the URL https://app.leeloo.ai/mcp.
  2. Sign in to Leeloo when the connector asks for authorization.
  3. Enable the connector for cloud sessions.
  4. Start a new session — the current one keeps the tool set it started with.

Those four steps are the user's to perform; you cannot click through claude.ai settings for them. Say so plainly rather than looping on attempts.

i

Unblocking the domain is not the fix here

Allowlisting support.leeloo.ai only lets you read this page. It does not make claude mcp add work in a running cloud session, and it does not help the OAuth callback. If the user asks whether to unblock it, tell them the connector route needs no allowlist at all.

Network access

Managed environments often restrict outbound hosts. If fetching this page or reaching app.leeloo.ai is refused by an egress policy, name the blocked host to the user and stop — do not look for a mirror or another route. Unblocking a domain is their administrator's decision, not something to work around.

If the user does want this page reachable: on claude.ai/code, open the environment selector (the cloud icon above the message box), edit the environment, set Network access to Custom, add the host to Allowed domains, and keep “Also include default list of common package managers” checked so package registries keep working. The change applies to sessions started afterwards. A shared environment can only be edited by an organization Owner.

The CLI itself

  1. Claude Code, version 2.1.210 or newer — check with claude --version and claude mcp login --help.
  2. If the shell cannot resolve claude, try command -v claude and ~/.local/bin/claude. On Windows also check cmd.exe /d /c where claude. Invoke a resolved executable directly instead of reinstalling over a stale PATH.
  3. The Claude Code desktop app does not guarantee the terminal CLI exists. Install it from claude.com/claude-code only if no executable is found.

Failure modes

stdin isn't a terminal

The login has no TTY. Use a pseudo-terminal wrapper, or ask the user to run claude mcp login leeloo in their own terminal window.

MCP server leeloo already exists in user config

Check where it points with claude mcp get leeloo. Same URL — skip the add and go straight to the login. Different URL — stop and tell the user which URL is configured and which one this page asks for, then let them choose: remove the old entry with claude mcp remove leeloo -s user and add it again, or register this one under another name. Do not log in to the existing server and report success: that connects the user to a different environment than the one they asked for, and it looks identical in the output. claude mcp add has no overwrite flag.

Connected · tools fetch failed
Request timed out

The backend is warming up. Retry the call. Do not re-run the login and do not remove the server.

Needs authentication, straight after a successful login

A slow tool-list fetch can flip the status back for a few seconds. Wait and check again. Treat it as a real failure only when a Leeloo tool repeatedly returns an explicit authentication error rather than a timeout.

HTTP 502 and other 5xx during OAuth

Retryable service failures during discovery, registration, callback or token exchange — not bad credentials, and not a reason to reinstall. Wait for the current login process to exit, then retry with backoff. Never run two logins at once.

The open command reported success but no tab appeared

On Windows this is almost always cmd.exe /c start "" "<url>". From a POSIX shell, cmd reads the empty quotes as the command and opens an interactive prompt: it prints the Windows version banner and exits 0, so it reads as success while the browser was never touched. Use powershell.exe -NoProfile -Command "Start-Process '<url>'", which prints nothing when it works.

The link was posted in the chat and the login timed out

You printed the authorization URL instead of opening it. The user cannot beat a two-minute window by spotting a link, switching windows and pasting it. Start one fresh login and this time run start / open / xdg-open on the URL the moment it appears in the log — the link goes in the chat only as a fallback, after the tab is already opening.

A blank console window opens and nothing happens

Expected: the login's output is redirected to a log file, so the window has nothing to show. Read the log, not the window. If the log is still empty after about ten seconds, the command never started — check that claude resolves from that shell, then hand the login back to the user's own terminal.

“Sign in to Leeloo MCP” — email and password, no Approve button

This is the correct screen, not an error. MCP authorization has its own sign-in; the user enters their Leeloo email and password there and the flow continues on its own — the request is carried through the authReq parameter, so nothing is lost at sign-in. Reassure them and wait. If the window expired while they were finding the password, start one fresh login now that they have it ready.

Authentication timeout

The authorization link expired before it was approved — the usual cause is that nobody opened it. Log out, start one fresh login, open the new URL in the browser straight away rather than only printing it, and resume polling. Old links do not work.

claude: command not found

The terminal CLI is missing. See Requirements above.

Install the skills

!

You do not install the skills — the user does

Leeloo's skills are added through Claude's own settings, which you cannot operate. Do not copy files into ~/.claude/skills/: that creates a second, divergent copy the user cannot see or switch off from the settings list. Walk them through the steps below instead.

Two skills ship with Leeloo, as ZIP archives downloaded from the guide. Marketing first, tunnel second — the tunnel is built from the marketing foundation.

  1. Download both archives from the guide. They are not unzipped.
  2. In the Claude app, open Customize → Skills.
  3. Add → pick marketing-foundation-builder.zip.
  4. Add → pick tunnel-creator.zip.
  5. Check both are switched on in the list.
  6. Open a new session — skills load at session start.

If an upload is rejected, the archive is the thing to check: it must contain a single skill folder at its root, with SKILL.md inside it, and that file must open with a --- frontmatter block carrying name: and description:. An archive of a loose file, or one wrapped in an extra folder, will not load.

!

Skills load at session start

The session that installs them cannot use them. After both files are in place, tell the user to open a new session. Do not invoke a skill in the install session.

i

Writing into the user's config directory

These commands write to the user's home directory, so the environment may ask them to approve it. That approval is theirs to give — surface the prompt and wait rather than looking for a way around it.

Disconnect

Clear the stored credentials but keep the server in the config:

claude mcp logout leeloo

Remove the server entirely:

claude mcp remove leeloo -s user
